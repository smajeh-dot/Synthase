# 0014: The compound register, `syn compound add`, `show` and `list`

## Context
The compound register is the first real command (M1, decision 0012). #32 builds its storage and the shared code that adds a compound. The `syn compound add` command that asks the questions is #37, split from #32 to keep each PR under the 400-line limit. Showing, editing, the extra fields and batches follow in #33 to #36. The issue left open where the register is saved, where the atomic weights for the molar mass come from, the prompt wording, and what happens with duplicate labels, wrong answers and invalid SMILES.

The owner chose all the triage defaults below for #32 (2026-10-17). The prompt and flag rules below are built in #37.

## Decision
- **Storage:** one SQLite file, `compounds.sqlite`, in the workspace next to `config.toml`. SQLite is built into Python, so there is no new dependency. The file is created the first time a compound is added.
- **Tables:** `compounds`, `batches`, `spectra` and `changes` (the change log) are all created at once. The schema version is kept in SQLite's `user_version`, starting at 1, so a later version of Synthase can upgrade the file. A file with a newer version than Synthase knows is refused with "update Synthase". #35 adds the characterisation, handling and safety columns as an upgrade to version 2 (see "Details settled for #35"). #36 may change the `batches` and `spectra` columns before anything is saved in them (see "Details settled for #36"). #36 moves to version 3 and #46 to version 4.
- **IDs:** `SYN-` and the row number, zero-padded to three digits (`SYN-001`). SQLite's `AUTOINCREMENT` makes sure a number is never used twice, even if a row were removed by hand. After `SYN-999` comes `SYN-1000`.
- **Shared command layer:** `synthase/compounds.py` does the work and raises `CompoundError` with a plain-language message. It never prints or asks anything. `synthase/cli.py` asks the questions and prints the results. The M2 app will call the same functions.
- **One quick write per command:** each command opens the file, writes everything in one transaction and closes it again. That reduces the chance of OneDrive syncing a half-written file. `/backup` (M5) is the proper safety net.
- **Molar mass uses RDKit's built-in standard atomic weights.** This is an exception to the rule that every scientific constant lives in the config: copying 118 atomic weights into the config would add nothing that can be checked better there. The formula comes from RDKit too. The full value is saved and shown to 3 s.f. (`CCO` gives C2H6O, 46.1 g/mol).
- **SMILES:** saved exactly as typed. A SMILES RDKit can't read is refused, and so is one with a space in it, because RDKit would silently ignore everything after the space. There is no check for the same structure entered twice under different labels.
- **Labels:** required, and unique when capitals and surrounding spaces are ignored. A repeat is refused: `"Test compound A" is already SYN-001. Choose another label.`
- **Class and status:** fixed lists from the roadmap. Capitals, hyphens and underscores are ignored, so `schiff-base` gives "Schiff base". Status defaults to planned.
- **Wrong answers:** guided prompts explain and ask again. Flags fail with the message and exit code 1, and nothing is saved.
- **Prompts and flags:** `syn compound add` with no flags asks for each field, and Enter skips any question except the label. With any flag it asks nothing, and `--label` is required. Running out of input (for example a closed pipe) cancels with "Nothing was added."
- **Change log:** adding a compound logs one row for each field filled in, with the date and time, an empty old value and the new value. Edits in #34 use the same table.
- **Details settled for #37** (the owner chose the triage defaults, 2026-10-17):
  - A repeated label is caught straight after it is typed, before the other questions.
  - A wrong answer in the prompts prints the message on its own line, then asks the same question again.
  - Ctrl+C partway through is treated like running out of input: `Nothing was added.`, exit code 1.
  - Flags without `--label` fail with: `Give the label with --label, or run "syn compound add" with no flags to be asked for each field.`
  - `syn compound` on its own shows the `compound` help, as a bare `syn` does.
  - Help text: `syn --help` lists `compound` as "keep track of the project's compounds, from idea to tested". `syn compound add --help` says: "Add a compound to the register. With no options, Synthase asks for each detail; press Enter to skip any but the label. With options, it asks nothing."
- **Details settled for #33** (the owner chose the triage defaults, 2026-10-18). The owner noted that the app in M2 gets its own interface, so this plain command-line look is not designed further now.
  - `syn compound show <ID>` prints the same field lines as `add`, leaving out blank fields, then a "Still missing:" list: `no class yet`, `no SMILES yet, so no formula or molar mass`, `no notes yet`. With nothing blank it prints `Nothing missing.` The #35 fields join the list when they arrive.
  - An ID can be typed as `SYN-001`, `syn-1` or `1`. Anything else gives `"abc" isn't a compound ID. IDs look like SYN-001.` An unknown ID gives `There's no compound SYN-042 in the register. Run "syn compound list" to see every ID.` Both exit with code 1.
  - `syn compound list` prints aligned columns (ID, Label, Class, Status, Formula, Molar mass (g/mol)) in ID order, with `-` in blank cells and labels never cut short. A count follows: `2 compounds.`, or `1 of 3 compounds (status: planned).` when filtered.
  - `--status` and `--class` take one value each, in the same forgiving forms as `add`. Together, a compound must match both. A value not on the list gives the same message as `add` and exit code 1.
  - An empty register prints `The register is empty. Add a compound with "syn compound add".` A filter that matches nothing prints `No compounds match (status: tested).` Both exit with code 0, and nothing is saved as CSV.
  - `--csv <file>` saves the same columns and values as the table, molar mass to 3 s.f., with blank cells left empty. The file is UTF-8 with a byte-order mark (`utf-8-sig`), so Excel on Windows shows every letter correctly. The path is taken as typed, relative to the current folder. (Replaced by decision 0015: a file name now goes in the folder set under `[folders]` in `config.toml`, or the workspace `results\` folder.) An existing file is replaced only after a yes to `<file> already exists. Replace it? [y/N]`. A file that can't be written, for example because Excel has it open, gives a plain message and exit code 1.
  - Reading never creates the register: `show` and `list` open it read-only, and only if it exists.
- **Details settled for #34** (the owner chose the triage defaults, 2026-10-18):
  - `syn compound edit <ID>` with no flags asks about the label, class, SMILES, status and notes in turn, with the current value in brackets (`SMILES [CCO]: `); a blank field shows no brackets. It opens with `Editing SYN-001: Test compound A. Press Enter to keep a value, or type - to clear it.` Wrong answers are explained and asked again, as in `add`.
  - With flags (`--label`, `--class`, `--smiles`, `--status`, `--notes`) it asks nothing except the confirmations, and changes only the fields given. A refused value exits 1 and saves nothing.
  - Filling in a blank field needs no confirmation. Changing or clearing a set one asks `Change the SMILES from "CCO" to "CCN"? [y/N]` (or `Clear the notes ("…")? [y/N]`) after every answer is in. Only yes changes it; anything else prints `Kept the SMILES as "CCO".` Status always has a value, so every status change asks too. With flags the same question is asked, and no input counts as no. There is no `--yes` shortcut.
  - `-` clears class, SMILES or notes. Label and status can never be blank. New notes replace the old ones; the old text stays in the history.
  - A new SMILES recalculates the formula and molar mass, and clearing it clears both. The history logs the SMILES only, because the formula and molar mass follow from it.
  - Every confirmed change is saved and logged in one step, with the date and time and the old and new values. The shared layer takes the confirmation question as a function, as `create_workspace` does, so the app can ask in its own way.
  - `syn compound history <ID>` prints `History of SYN-001: Test compound A`, then one line per change, oldest first: `2026-10-18 16:42  SMILES  CCO -> CCN`, with `(blank)` for an empty value.
  - `syn compound archive <ID>` asks `Archive SYN-002 (Test compound B)? It stays in the register but is hidden from "syn compound list". [y/N]`. `syn compound restore <ID>` undoes it without asking. Both are logged (`archived  no -> yes`). An archived compound can still be edited, and keeps its label, so a new compound can't reuse it.
  - `list` leaves archived compounds out and says so in its count, `2 compounds (1 archived, hidden; add --all to see it).`; `list --all` shows them with `(archived)` after the label. `show` heads the card `SYN-002: Test compound B (archived)`.
- **Details settled for #35** (the owner chose the triage defaults, except that melting points are in kelvin, 2026-10-18):
  - The register moves to schema version 2, which adds the characterisation, handling and safety columns. A version 1 file is upgraded by the first command that writes to it. Until then, `show` and `list` read it through an upgraded copy in memory, so reading still never changes the file.
  - **Melting points are in kelvin**, always, whatever `units.temperature` says. They are typed as `455-457`, `455–457` or `455 to 457`, with an optional `K`. A single number is a sharp melting point (width 0). They are shown as `455–457 K`. A range typed high to low gives `The melting range runs from high to low (457 to 455 K). Type the lower temperature first.`, and 0 K or below is refused.
  - **Purity flag:** a melting range is flagged only when it is wider than `melting_point.purity_range`, so a range exactly as wide as the rule passes. The width is rounded to 6 decimal places first, so that, say, 457.1 − 455.1 counts as exactly 2. A width in kelvin equals the same width in °C, so the rule's value doesn't change; the template's unit is now `K`. The card shows `! The melting range is 2.5 K wide, wider than the melting-point purity rule (2 K), so the sample may not be pure.`, followed by the rule's unverified warning while it has one.
  - **Rf:** one value per compound, from 0 to 1 inclusive. Outside that: `An Rf value is between 0 and 1. "1.3" isn't.` An Rf can't be saved without its solvent system (free text), and the solvent system can't be cleared while the Rf stays.
  - **Coloured:** a yes/no answer, separate from the appearance text, saved as the `coloured` field of a compound (blank means not recorded) so that `/plate design` (M3) can read it. The question is `Coloured in solution, so it needs a compound-only blank? (yes/no)`.
  - **DMSO stock concentration:** a number above zero with a unit from a fixed list: mg/mL, µg/mL or mM. `u` may be typed for `µ`. It is saved as typed, with no conversion.
  - **Risk assessment:** one answer, `no` or the date it was done, typed as `2026-10-18` or `18/10/2026` (UK order), saved and shown as 2026-10-18. A date that doesn't exist (`"31/02/2026" isn't a real date.`) or is in the future is refused.
  - Appearance and colour, solubility, storage conditions and hazard notes are free text, like notes.
  - **Prompts:** `add` and `edit` with no flags ask the first five questions as before, then one question per group, such as `Add characterisation details (melting point, Rf)? [y/N]`, before asking that group's fields.
  - **Flags:** `--mp`, `--rf`, `--rf-solvent`, `--appearance`, `--coloured`, `--solubility`, `--dmso-stock`, `--storage`, `--risk-assessment` and `--hazards`. With `edit`, `-` clears any of them. Changing a set value asks first, as for the other fields, and every change is logged with its value as shown (`455–457 K`, `yes`).
  - **Card:** after the first fields come `Characterisation`, `Handling` and `Safety` headings with their filled fields; a group with nothing filled is left out. "Still missing" adds `no melting point yet`, `no Rf value yet`, `no appearance yet`, `not recorded whether it is coloured`, `no solubility yet`, `no DMSO stock concentration yet`, `no storage conditions yet`, `no risk assessment recorded` (or `risk assessment not done yet` after a no) and `no hazard notes yet`.
  - `list` and its CSV are unchanged.
- **Details settled for #36** (the owner chose the triage defaults, 2026-10-18):
  - The register moves to schema version 3, which adds a `kind` column to `spectra`. The `batches` columns already fit. Both tables were still empty everywhere.
  - `syn compound batch <ID>` adds a batch, and `syn compound spectrum <ID> <FILE>` links a spectra file. With no options, each asks its questions; with options, they ask nothing.
  - **Batch date:** typed as `2026-10-18` or `18/10/2026`; blank means today. A date that doesn't exist, or is in the future, is refused.
  - **Mass made:** a number above zero with `mg` or `g` (`152 mg`); a bare number is refused. It is saved in grams and shown to 3 s.f., in mg below 1 g and in g from 1 g up.
  - **Yield:** a percentage (`64.2`, or `64.2%`), shown to 3 s.f. Below 0 is refused. Above 100 is saved, with `A yield over 100% usually means the product is still wet or impure.`
  - A batch needs its mass, its yield or both. The date is always saved.
  - Batches are numbered per compound in the order they are added: batch 1, batch 2 and so on.
  - Adding a batch never changes the status. If the compound is still planned, Synthase prints `SYN-001 is still "planned". Change it with "syn compound edit SYN-001 --status synthesised".`
  - The shared function `add_batch` takes the date and numbers, not typed text, so `/yield` (M3) can pass what it has worked out. It checks them the same way.
  - **Spectra files must be inside the workspace.** A relative path counts from the current folder, or from the workspace if there is no such file in the current folder. The link is saved relative to the workspace, so moving the whole workspace keeps it working. A file outside is refused: `Spectra files must be inside the workspace (<workspace>). Copy it in, for example into a "spectra" folder, then link it.` A missing file gives `There's no file at <path>.` Linking the same file to the same compound twice is refused.
  - **Kind of spectrum:** optional, one of IR, 1H NMR, 13C NMR, mass spec, UV-vis or other, in the same forgiving forms as class.
  - **Card:** `syn compound show` adds a `Batches` section (`1  2026-10-18  152 mg  64.2%`, with `-` for a blank) and a `Spectra` section (`IR  spectra\SYN-001 IR.csv  (added 2026-10-18)`). A linked file that has since moved or been deleted shows `(file not found)`. "Still missing" adds `no batches yet` and `no spectra linked yet`.
  - The change log records `batch  (blank) -> 1: 2026-10-18, 152 mg, 64.2%` and `spectrum  (blank) -> IR spectra/SYN-001 IR.csv`.
  - Batches and links can't be corrected or removed yet; that is a separate issue. (#46 adds this; see "Details settled for #46".)
- **Details settled for #46** (the owner chose the triage defaults, 2026-10-18):
  - The register moves to schema version 4, which adds a `removed` column (the date and time) to `batches` and `spectra`. Removing sets it; nothing is ever deleted. A version 3 file is upgraded by the next command that writes to it.
  - Three commands: `syn compound edit-batch <ID> <N>`, `syn compound remove-batch <ID> <N>` and `syn compound unlink <ID> [FILE]`.
  - **Batch numbers never change.** A batch's number is its place among all the compound's batches, removed ones included, so removing batch 2 leaves batches 1 and 3, and the next batch added is 4.
  - **`edit-batch`** works like `edit`. With no flags it opens with `Editing batch 1 of SYN-001: Test compound A. Press Enter to keep a value, or type - to clear the mass or yield.`, then asks `Date made [2026-10-18]: `, `Mass made [152 mg]: ` and `Yield in % [64.2%]: `. Flags are `--date`, `--mass` and `--yield`, as in `batch`. Filling a blank value needs no confirmation; changing or clearing a set one asks `Change batch 1's mass from "152 mg" to "125 mg"? [y/N]`, and anything but yes prints `Kept batch 1's mass as "152 mg".` The date can't be cleared, and a batch still needs its mass, its yield or both.
  - **Removing** asks `Remove batch 2 of SYN-001 (2026-10-18, 140 mg, 50.0%)? It is hidden from the card but kept in the history, and the other batches keep their numbers. [y/N]` or `Unlink IR spectra\SYN-001 IR.csv from SYN-001? The file itself is not touched. [y/N]`. `unlink` with no FILE lists the linked files, numbered, and asks `Which one? (1-2)`. A FILE is matched against the path on the card, ignoring capitals and `\` versus `/`, so a file that has since moved can still be unlinked.
  - **History:** one line per corrected value, `batch 1 mass  152 mg -> 125 mg`; a removal is `batch  2: 2026-10-18, 140 mg, 50.0% -> removed` or `spectrum  IR spectra/SYN-001 IR.csv -> removed`.
  - **No restore command.** A removal made by mistake is undone by adding the batch (under a new number) or linking the file again; an unlinked file can be linked again. The card shows the gap in the batch numbers with no extra line; the history explains it.
  - A removed batch can't be corrected or removed again: `Batch 2 of SYN-001 was removed on 2026-10-18.` An unknown number gives `SYN-001 has no batch 4. Its batches are 1 and 3.`
  - A spectrum's kind can't be corrected on its own: unlink the file and link it again with the right kind.
- **Details settled for #50** (the owner chose the triage defaults, 2026-10-18):
  - **Display text has its own module.** `synthase/compound_text.py` builds the card, the list's count line and the history lines. Like `compounds.py`, it never prints or asks anything. `cli.py` prints what it returns. `compounds.py` stays the part that reads and saves the register.
  - **The app gets rows as well as lines.** `card()` gives a title, sections (a heading, then (name, value) rows or a table's cells, then any warnings) and the "Still missing" list. `card_lines()` turns that into the exact lines `syn compound show` prints. `history_rows()` and `history_lines()` do the same for the change log. The app can lay the rows out its own way (#57) and still use the same words.
  - **The count line moves too.** `list_summary()` gives the line under the list table, or `No compounds match (…).` / `Every compound is archived. Add --all to see them.` when nothing is shown. `The register is empty. Add a compound with "syn compound add".` stays in `cli.py` because it names a command-line command.
  - **One-line messages stay in `cli.py` for now.** `Added …`, `Saved … changes`, `Archived …`, `Restored …` and the confirmation questions don't move. The questions belong to #51, and the messages can follow when the app needs them.
- **Details settled for #51** (the owner chose the triage defaults, 2026-10-18):
  - **The questions have their own module.** `synthase/compound_questions.py` describes each guided flow (`add`, `edit`, `batch`, `edit-batch`, `spectrum`, `unlink`) as a list of questions. Each question has its prompt, the current value where there is one, whether Enter may skip it, the check that turns typed text into a value or a plain-language error, and, where it depends on earlier answers, whether it is asked at all. Like `compound_text.py`, it never prints or asks anything. `cli.py` works through the lists with `input()`. The app (#56) will work through the same lists.
  - **Group questions are in the lists.** `Add characterisation details (melting point, Rf)? [y/N]` and the other two are `[y/N]` questions. The fields of a group are only asked after a yes. Only `yes` or `y` counts as yes, as for every confirmation.
  - **Each flow carries its opening lines,** such as `New compound. Press Enter to skip any question except the label.` and, for `unlink`, the numbered list of linked files. The app shows the same words.
  - **The change confirmation's wording moves too.** `Change the … from "…" to "…"? [y/N]`, `Clear the … ("…")? [y/N]` and `Kept the … as "…".` are used by `edit` and `edit-batch`, and the app needs them for #58. The archive, remove-batch, unlink and CSV-replace confirmations stay in `cli.py` until the app needs them. (The CSV question moved to `tables.py` in #57, and the other three moved to `compound_questions.py` in #59.)
  - **Running out of input at a `[y/N]` question still counts as no,** as before, so `syn compound add` carries on to the next question. Running out of input at any other question cancels with the same message as before.
- **Wording:** after adding, `syn compound add` prints `Added SYN-001: <label>`, each filled field, and `Add more details later with "syn compound edit SYN-001".` That command arrives in #34.

## Consequences
- The register is a single file, so backing up or moving the workspace takes it along.
- SQLite files can't be read in a text editor. `syn compound show` and `list` (#33) are the way to read the register.
- Molar masses follow the atomic weights of the installed RDKit version, which may change slightly between versions.
- Melting points read in °C, from the literature or the apparatus, must be converted (add 273.15) before they are typed. A °C value typed by mistake is accepted as a much lower kelvin value.
- The command-line tests read the register through `list_compounds` (#33). The register tests still read the file with `sqlite3`, because they check the tables and the change log themselves.
